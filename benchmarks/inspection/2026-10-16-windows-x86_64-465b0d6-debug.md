## Scope

This inspection checks the Windows-target counterpart of the representative macOS DWARF evidence without claiming a native Windows run. From the clean macOS host and the checked-in `benchmarks/fixtures/native-debug.mir` fixture, the test:

1. emits `x86_64-pc-windows-msvc` COFF objects for the add, minimum, and host-callback functions;
2. validates their C13 symbol, line, checksum, string, and type records plus function-relative relocations;
3. links the objects into a PE DLL and PDB with the pinned Rust toolchain's `lld-link`;
4. validates the PE RSDS/PDB identity, the PDB MSF signature, and retained source/function strings; and
5. asks Apple LLDB to resolve each linked function to the expected MIR source line and list the mapped source file.

On a Windows host the same integration test uses `link.exe`; the LLDB inspection is macOS-only. This capture therefore closes object-to-linked-PDB format and source-mapping evidence, but not the separate Windows CI object-link-run or benchmark tasks.

The macOS test discovers `lld-link` under the pinned Rust sysroot and supplies that sysroot's `libLLVM.dylib` through `DYLD_LIBRARY_PATH`. It links with `/dll /noentry /nodefaultlib /debug:full /force:unresolved`; the last option permits the representative callback import to remain unresolved because this is a debug-link inspection, not an executable Windows runtime test.

## Object results

The host-independent structural test passed for all representative source-mapped objects. Each object has a C13 `.debug$S` section containing:

- `S_OBJNAME`, `S_COMPILE3`, `S_GPROC32_ID`, `S_FRAMEPROC`, `S_PROC_ID_END`, and `S_BUILDINFO` records;
- a relocated procedure code offset and section index;
- a line fragment whose relocated function offset and section index target the exported function;
- a file-checksum entry and string-table entry for `benchmarks/fixtures/native-debug.mir`; and
- four exact COFF relocations: two `IMAGE_REL_AMD64_SECREL`/section-offset records and two `IMAGE_REL_AMD64_SECTION`/section-index records.

Each object also has a C13 `.debug$T` section with argument-list, procedure, function-ID, string-ID, and build-information records. Type records include their CodeView padding in the record length, which is required for LLD to accept the stream.

Selected source rows validated by the test are:

| Function | Validated line/column rows | Function-start mapping |
| --- | --- | --- |
| `prototype_add` | `2:3`, `3:3` | `2:3` |
| `prototype_min` | `9:3`, `11:3`, `13:3` | `9:3` |
| `prototype_host_callback` | `17:3`, `18:3` | `17:3` |

The first semantic row is extended to code offset zero so debugger lookup covers the generated prologue. Later rows retain their backend-provided machine-code offsets.

## Interpretation

- Representative Windows x86-64 COFF objects now carry validated source-driven CodeView records through LLD into a linked PDB.
- The linked PDB preserves function-to-source mappings that an independent debugger can resolve.
- This satisfies the Milestone 0 Windows CodeView/PDB and source-mapping evidence task.
- It does not prove native Windows execution, MSVC `link.exe` behavior on a remote runner, Windows performance, source-language parameter/local-variable locations, unwind metadata, optimized stepping, or JIT debugger registration. The Windows CI object-link-run and benchmark tasks remain open.
