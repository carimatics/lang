```text

```

The tool builds the compiler and SDK builder together, consumes their exact successful Cargo JSON output and copies the selected Rust artifacts/native support archives. Keep build outputs unchanged during assembly. Assembly uses Cargo; installed application linking must use bundled artifacts and the exact recorded rustc release/commit without Cargo, registry access or repository paths.

The SDK contains `bin/lang` (`lang.exe` on Windows), `lib/` Rust artifacts, applicable `native/` archives, `include/lang/runtime.h`, `startup/` templates, these bilingual instructions and `sdk.json`. Copying the SDK directory does not change its build identity.

SDK/bin/lang native --output program application.lang
```

It must not retain a raw context/client or call after the Rust binding scope ends. The unsafe matching-image obligation includes unwind. SDK/bin/lang link-native --sdk SDK --package c-program --host c-host.rs --object client.o --output c-application
```

## Public component-v1 API

Component C v1 is stable under [stabilized RFC 0033](rfcs/0033-component-v1-compatibility.md), verified 2026-10-27 JST. The public 32-entry exact-size/version surface, statuses and ownership/failure contracts are frozen; previous headers/generated clients pass actual macOS/Windows execution at `9e78f2d`. The [migration record](evidence/2026-10-27-m3-migration-9e78f2d.json) retains provenance and full validation. Both-host isolated seven-profile SDK startup also passes. An incompatible C extension needs a new version/namespace; private Rust/SDK ABI requires an exact build and rebuilding. Unsupported stored formats require re-encoding/recompilation from source with matching tools.

`lang_component_v1_get_api(1, sizeof(lang_component_v1_api), &api, &error)` publishes one immutable complete table with all 32 entries non-null. Initialize the exact error header first. An unknown API version returns 3; a mismatched table size, null output/error pointer or incorrect initialized error header returns 2. Rejected queries leave the table output unchanged. The returned table has process lifetime; it supplies no engine, resource, grant or executable authority. Concrete requests keep exact size/version headers and zero reserved fields, and live handles obey the documented owner-thread/lifetime rules.

Modes are VM 0, JIT 1 and exact-SDK AOT 2. VM/JIT `module_load` admits the explicit source+IDL or revalidated artifact profiles; AOT requires `module_bind_native` and the Image factory below. `context_resource_drop` validates the current owning receipt and original holder/table, refuses borrowed/stale/transferred/in-use claims, and retires through the original cleanup Session. It can complete cleanup after interruption without granting guest reentry. A failed destructor yields a retained immutable report and poisons the original execution; result release is separate from owner retirement. Public-query C fixtures cover VM/JIT/AOT; B01 both-host conformance and B02 old-client migration pass. Public C v1 is stable at RFC 0033's scope, preserving the private SDK/image exact-build boundary.

## SDK-owned component Image

The native Image entry in RFC 0027 (2026-10-27 JST, experimental) takes the complete version-3/component `package.json`, the existing SDK `Input` (target/build ID and semantic/native bytes), the actual generated `bindings.rs` bytes, the real code owner/resolver and finite preparation limits through `unsafe native::component::Image::new`. It checks all four role sizes/hashes, canonical snapshots, selected export and record/target/build correspondence, then retains the actual code owner. The C `native_image.program` points to this exact SDK's Image and metadata is the original manifest. Keep a movable Rust value in stable storage such as `Box<Image>` while its pointer is used. Successful registration retains required data and its supplied C owner through the final module/instance/binding/result/code lease; refusal preserves caller ownership.

The SDK Rust facade `component_embedding::gateway` connects mode 2, `module_bind_native` and the existing C calling signatures. Passive manifest host/exact-SDK checks precede private-pointer access; no unknown constructor, filesystem discovery or VM/JIT fallback is used. An image executes only its recorded selected export; another otherwise valid export returns unsupported-profile. Actual instance grants/providers remain mandatory: packages and hashes grant no authority. Native code is trusted; this supplies neither cross-SDK Rust ABI stability nor a sandbox. E01 tracks the complete public-query integration and installed acceptance described above.

The optional second argument of `startup/component-producer.rs OUTPUT [HEADER]` emits `component-api.h` and `component-client.c` as explicit host inputs without changing package roles. The SDK includes `startup/component-client.c.in` and `startup/component-gateway-host.rs`. Compile generated C with the normal target compiler and pass its object to the existing `link-native --host ... --object ...` entry. `tools/check-native-sdk-install.py` adds `component-gateway` to the six existing profiles, removing all package/private SDK/link inputs before checking C gateway 42, panic, reuse, fuel refusal, owner retirement and zero inventory. E16 isolation evidence is recorded on the M3 board, separately from actual Windows execution.

## Trusted mixed Rust host (experimental)

An embedding Rust host can build `dap::mixed::NativeHosts`, register explicit `extern "C" fn(i64) -> i64` callbacks and construct `dap::Server::with_native_hosts` or call `dap::serve_stdio_with_native_hosts`. Callback code must remain alive for the server lifetime and handle interruption cooperatively. The ordinary `lang dap` server still has no host grants; source/protocol cannot register code. Use the runnable fixture `cargo run --example mixed-dap` with a DAP launch selecting `{"mode":"mixed","root":"/absolute/repository/examples/packages/debug_mixed","manifestPath":"Lang.json"}` after initialize, then configurationDone.

The registered callback calls `dap::mixed::pause()` on its original worker. The adapter retains the same VM HostCall and exact source callers while displaying bounded native physical PCs followed by VM frames. Physical correspondence uses an active call scope and exact PC suffix, with no symbol-string matching or native Rust source reads. Native frames currently use address labels. Continue resumes that call once; disconnect interrupts the cooperative pause. Values and native instruction stepping are unavailable during the native callback pause; ordinary paused VM inspection stays available. This is a trusted host bridge, not arbitrary attach/loading or a native sandbox. D04B local bridge validation is in progress; D04 both-host protocol/failure and D05 lifecycle acceptance remain required.
