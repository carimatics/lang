## Findings and resolutions

- **R01 — P1: callback state borrowed before owner-thread rejection.** `component::context_check`, allocator identity inspection and resource/buffer operations could form a Rust reference to `State` before rejecting a foreign thread. In particular, `with_call` formed `&mut State` first. Reuse one raw immutable-identity preflight before any state reference, including gateway and child entry. Preserve existing status codes, output preservation, live-scope/control checks and public ABI. Real VM/JIT/native callback tests now check the inspection/resource/buffer refusal paths as well as child reentry; the owner resumes normally. No concurrent guest execution or new cross-thread authority is introduced.
- **R02 — P2: incomplete M3 evidence could be published.** The harness counted six rows without checking six distinct workload identities, and accepted two VM captures as VM/JIT when counters matched. It also trusted source hashes and timing summaries. Validate matrix identities, expected source/result/digest, backend/schema/profile, integer samples/counters, recomputed distribution summaries, warmups and per-call/final retirement. Build with `--locked`. Eight tests replay the real historical capture and reject duplicated, substituted or corrupt evidence; both native CI workflows run M2/M3 evidence validators. Ignore the M3 harness's generated Python cache, as the M2 harness already does, so running validation preserves clean-checkout provenance.
- **R03 — P2: lifecycle and user guidance contradicted completed implementation.** RFC 0002 and RFCs 0022–0026 now record implemented scope and named evidence. RFCs 0003–0005 remain accepted broad policies, with current implemented follow-ups distinguished from future choices. Original acceptance decisions and dated source evidence are preserved. README no longer calls source async, M3 or both-host SDK startup unfinished, and documents current task/component/SDK versions. RFC translation checks now compare section hierarchy and fenced-example languages in addition to status/dates, so a lost source section cannot pass unnoticed.
- **R04 — P2: current architecture and board obscured by superseded checkpoints.** The architecture had regrown to roughly 130 KB and the completed M3 board to 336 KB, mixing current claims with hundreds of old incomplete-scope paragraphs. Preserve both previous bodies verbatim in bilingual [architecture](architecture-m3-history.md) and [board](milestone-3-history.md) archives. Keep the current overview, all 79 delivery rows/evidence commits, all 15 gates and final **110 + 99 − 209 = 0** reconciliation visible. Add the missing current native/package/component version domains. This changes no accepted semantics, gate, estimate or historical evidence.
- **R05 — P2: installer trust prerequisite crossed milestone order.** M4 requires an install/update tool before M5's signed package-publication work. Its entry audit now requires toolchain trust roots, signed release metadata and atomic update/failure recovery to be defined in an accepted installer design before download/install is implemented. M5 retains registry-package publication/provenance. The milestones remain unactivated and gate weights unchanged; actual delivery estimates must be derived on activation.

- **R06 — P2: the macOS CI deadline lacked allowance for the current conformance workload.** The job still had a 30-minute limit; the earlier M3 local baseline took approximately 32.8 minutes, and this review's full test run took 73.5 minutes. Set a finite 120-minute job limit to allow compilation and native conformance. All validation stages remain enabled. CI runner timing and results are verified separately for the pushed revision.
