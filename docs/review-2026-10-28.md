## Findings and resolutions

- **R01 — P1: artifact publication could destroy an imported source.** `lang compile --output helper.lang main.lang` succeeded when `main.lang` loaded `helper.lang`, replacing the module with bytecode. The old check protected only the entry file. Publication now compares the destination's canonical identity against every source admitted by the root-checked file loader. Root, child, transitive module and symlink alias refusal preserve source bytes; ordinary artifact replacement still works. The new regression first failed with exit 0 on the destructive case, then passed after the fix. [RFC 0011](rfcs/0011-ownership-artifacts.md) records the delegated correction and compatibility consequence before implementation. Source names from decoded artifacts still grant no filesystem authority; concurrent hostile filesystem replacement is outside this CLI check's guarantee.
- **R02 — P2: incomplete or invalid M3 observations could be published.** Equal VM/JIT dictionaries missing `fuel` passed parity validation; a task row could omit allocation requests, and negative/string/boolean/overflowing preparation durations or incomplete preparation usage passed. Version-1 evidence now requires the complete task/component/preparation counter sets and unsigned integer preparation durations. New tests corrupt the real archived capture; the existing capture remains accepted and unchanged. This strengthens evidence admission without adding a performance threshold or claiming new measurements.
- **R03 — P2: RFC follow-ups contradicted completed work.** Twenty RFC pairs retained actionable “unverified”/“separate work” statements for completed native lowering, previews, SDK startup, accounting and Windows execution. Reconcile their open-question sections and add explicit current scope where needed, while preserving acceptance decisions, dated checkpoints, version domains and non-goals. RFCs 0030–0032 now link completed I08/both-host evidence instead of implying Windows is unavailable. Public C v1 stability does not stabilize private SDK or stored formats.
- **R04 — P2: current development guidance could misdirect subsequent work.** README still deferred adding the already implemented JIT. The roadmap's leading 133-delivery count could be read as an M2/M3 total, and M4's package path lacked an explicit first end-to-end fixture independent of M5's registry. Correct the JIT guidance, label the M2 count, and require the existing M4 gates to start with package creation/local dependency/build/run/test/offline lock replay, explicit source authority, and the already required installer trust decision. No gate, estimate, completion count or future milestone is activated by this review.
